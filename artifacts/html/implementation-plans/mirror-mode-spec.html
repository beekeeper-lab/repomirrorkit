Goal & decisions

Point RepoMirrorKit at any readable Git repo and get back an output directory that is a self-contained requirements package: no original source, no .git history, and beans complete enough that an agent — in Vue, React, Flutter, anything — can rebuild a functionally identical application from the output directory alone. Visual design is out of scope; behavior, contracts, data, screens-as-functions, business rules, navigation, and seed data are in scope. This doubles as the rig for comparing models and instruction variants on long-running builds: same beans, different agent, measurable output.

Strategy & phases

Five phases, each independently shippable. Phase 1 alone delivers the cleanup ask end-to-end; Phases 3–5 mostly approve and sequence existing recreation-roadmap beans rather than invent new work.

Phase 1 — --mirror mode + Stage H cleanup net-new · ship first

M1.1 Config & CLI

  • HarvestConfig.mirror, keep_source, cleanup (resolved: mirror → on, else off; --cleanup forces on; --keep-source forces off and wins).
  • --mirror: missing ANTHROPIC_API_KEY or anthropic package → hard error, exit 3 with actionable message. Forces llm_enabled=True; flips --fail-on-fidelity default to true; selects the mirror fidelity threshold profile (minimal version ships here).

M1.2 Provenance capture (Stage A)

  • CloneResult gains head_sha (git rev-parse HEAD post-checkout).
  • Persist {repo_url, ref, head_sha, harvested_at} to state.json; render a provenance block atop REQUIREMENTS.md: "Source references refer to <url> @ <sha>; the source tree is not included." This keeps every source_refs entry meaningful after deletion.

M1.3 Stage H — cleanup (harvester/cleanup.py, new)

Runs only after Stages A–G all succeed (any failure skips cleanup so the working copy survives for debugging). Safety invariants, all mandatory:

  1. Target is exactly output_dir / "repo", resolved, inside output_dir, not a symlink.
  2. state.json must record that Stage A cloned into this directory. Never delete a repo/ the harvester didn't create.
  3. Sanity check the target contains .git/; if state confirms the clone but .git is absent, proceed with a warning.
  4. After rmtree, walk output_dir and assert no .git remains anywhere; fail loudly otherwise.

Record {removed, files_removed, bytes_freed, completed_at} in state; append "H" to the stage list; structlog summary.

M1.4 Resume semantics

  • --resume with repo/ missing → force re-clone (fix at pipeline.py:256-265) instead of failing in Stage B.
  • If recorded head_sha differs from the re-cloned HEAD (and no --ref pin), warn that recorded line numbers may have drifted.

Phase 2 — Verbatim rule capture net-new · exactness

Policy (D1): verbatim = exact literals copied into structured fields — regex patterns, thresholds, enum members, defaults, error-message strings, status codes, formulas re-expressed neutrally (total = subtotal × (1 + tax_rate)) — never pasted source statements. Secret- and PII-shaped literals are redacted per cross-cutting safety rules, and every redaction is surfaced to the operator — silent redaction hides a finding the repo owner needs to act on.

  • M2.2 Templates: ## Validation rules and ## Errors become populated tables. Every would-be TODO: is either filled or converted to an explicit gaps: entry — in mirror output the literal TODO: must not appear, making placeholder_free_beans = 100% achievable and honest (absence is declared, not silent).
  • M2.3 Analyzers: API error responses + status codes (Flask abort, FastAPI HTTPException); model defaults, enums, check constraints, indexes; BEAN-065 (BusinessRuleSurface) adopts the verbatim policy as its output contract.
  • M2.4 LLM prompts: quote exact values, never emit code blocks, and return a new exact_rules: [{subject, rule, value, error_message, source_ref}] field rendered into the M2.2 tables.
  • M2.5 Sensitive-findings surfacing: every captured literal passes secret/PII detectors before landing in a bean. Redaction writes a typed placeholder ([REDACTED:aws-access-key], [REDACTED:email]); the raw value is never persisted anywhere — not in beans, logs, or the report. Each finding records category, detector kind, file:line in the original repo (meaningful via provenance), affected bean, and placeholder. Surfaced three ways: reports/sensitive-findings.{md,json}, a prominent end-of-run CLI warning ("N sensitive values found and redacted — rotate any real credentials"), and a one-line count rollup in REQUIREMENTS.md. Exit code unchanged; a --fail-on-secrets gate can come later.

Test plan

  • Unit: every M1.3 safety invariant — wrong dir, symlink target, no state record, missing .git, failure-path skip; config validation for the mirror/key matrix.
  • Integration (fixtures): mirror run on python-flask → repo/ absent, zero .git under out/, beans present, provenance in state.json + REQUIREMENTS.md; --keep-source preserves repo/; --resume on a cleaned dir re-clones and completes.
  • Exit codes: mirror without key → 3; gaps → 2; fidelity fail → 4.
  • Phase 2+: assert zero literal TODO: in mirror-run beans; exact-rule tables populated on both fixtures; no code blocks in bean bodies.

Rollback: Phase 1 is flag-gated — default (non-mirror) behavior is unchanged, so rollback = don't pass --mirror/--cleanup. Stage H itself is irreversible per run by design (that's the point); the guard is that it never runs on failed pipelines and --keep-source always wins.

Definition of done

  • harvest --repo <fixture> --mirror exits 0/2 with repo/ gone and zero .git anywhere under the output directory
  • Provenance (URL, SHA, date) recorded in state.json and REQUIREMENTS.md; --resume on a cleaned dir re-clones instead of failing
  • Mirror-run beans contain zero TODO:; unknowns appear as declared gaps
  • Exact-rule tables (validation, errors, defaults, enums) populated for both fixtures; no source-code blocks in beans
  • Secrets/PII redacted to typed placeholders and reported to the operator (reports/sensitive-findings.md + CLI warning); raw values appear nowhere in output or logs
  • build-manifest.json orders all beans as an executable DAG with per-bean Gherkin verification pointers
  • BEAN-078 harness: agent rebuild from output alone scores ≥90% Gherkin scenarios on both fixtures
  • Mirror fidelity gates run in CI and fail on regression
